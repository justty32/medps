第 3 站 common/ — actor 身分層

5 個檔案，共 172 行 · 對照 CODE_TOUR_world_actor.md

common/ 是「可用於多數 Zone 子類的組件」。actor（地點/部隊的共同基底）在 ECS 裡不是 C++ 父類，是一組共用元件：身分＝Name＋Owner；家族＝Location{kind} 或 Unit{kind}（互斥，一個 actor 只屬一族）；放置＝Position（world/components/，見第 4 站）——刻意與身分分離，spawn 不掛。

種類（kind）不是 enum，是資料驅動的 def：LocationKind{id}/UnitKind{id}＋Name掛在 root 的定義實體上；actor 以穩定 uint64_t id 參照 def（跨 registry 安全，比照 zone id / Owner.faction）。要新增種類＝多建一個 def 實體，不改任何 enum。

看什麼

  • Name{value}：actor 顯示名，兩大家族共用。 name.h:7
  • Owner{faction}：陣營穩定 id，0=無主/中立。 owner.h:8
  • LocationKind{id}：地點種類 def，掛在 root。 location.h:12
  • Location{kind}：地點 actor 的家族 tag，kind 參照 def id。 location.h:23
  • UnitKind{id}：部隊種類 def，掛在 root。 unit.h:10
  • Unit{kind}：部隊 actor 的家族 tag。 unit.h:21
  • require_root：fail-fast 檢查 def 只能掛在 root，否則 throw。 actor.h:32
  • define_location/define_unit：在 root 建種類 def。 actor.h:40
  • find_location_def：依 id 在 root 線性掃找 def，找不到回 entt::null。 actor.h:59
  • spawn_location/spawn_unit：在某 zone 建 actor（Name+Owner+家族 tag）。 actor.h:74
讀完該能回答：actor 的「基底」在這個 codebase 裡是什麼形式？為什麼 kind 用 def 實體而不是 enum？

14// actor＝「有身分、被玩家指涉、擺在世界裡」的實體，是地點（Location）與部隊（Unit）
15// 兩大家族的共同基底。在 ECS 裡「基底」不是 C++ 父類，而是一組共用元件：
16// 身分 = Name ＋ Owner
17// 放置 = Position（由放置流程另掛，刻意與身分分離——見 world/components/position.h）
18// 家族 = Location{kind} 或 Unit{kind}（互斥，一個 actor 只屬一族）

20// 種類（kind）不是寫死的 enum，而是**資料驅動的 def**：def 是住在 root 的實體
21//（LocationKind{id}／UnitKind{id} ＋ Name），actor 以穩定 id 參照它（跨 registry
22// 安全，比照 zone id / Owner.faction）。要新增一種地點/部隊＝多建一個 def 實體，
23// 不改任何 enum；將來 Ruleset 落地時 def 由檔案載入、id 由登錄機制發號。
24namespace actor {

26// ---- 定義（一律建在 root zone）----
27//
28// def 類型一定掛在 root（root 放全局實體＋規則定義）。define_* 吃 Zone& 並
29// fail-fast 檢查——傳非 root 進來＝呼叫端邏輯錯，直接 throw、不靜默寫到別的 zone。

31namespace detail {
32inline void require_root(const Zone& z, const char* who) {
33 if (z.id != ZONE_ROOT)
34 throw std::runtime_error(
35 std::string(who) + ": def 只能掛在 root zone，收到 zone id=" + std::to_string(z.id));
36}
37} // namespace detail
38
39// 定義一種地點：LocationKind{id}＋Name{name}。回傳 def 實體。
40inline entt::entity define_location(Zone& root, uint64_t id, std::string name) {
41 detail::require_root(root, "actor::define_location");
42 auto e = root.reg.create();
43 root.reg.emplace<LocationKind>(e, id);
44 root.reg.emplace<Name>(e, std::move(name));
45 return e;
46}

48// 定義一種部隊：UnitKind{id}＋Name{name}。回傳 def 實體。
49inline entt::entity define_unit(Zone& root, uint64_t id, std::string name) {
50 detail::require_root(root, "actor::define_unit");
51 auto e = root.reg.create();
52 root.reg.emplace<UnitKind>(e, id);
53 root.reg.emplace<Name>(e, std::move(name));
54 return e;
55}

57// 依 id 找地點 def（在 root），找不到回 entt::null。線性掃——def 數量小，
58// 需要時再上索引（比照 zone 的 unordered_map）。
59inline entt::entity find_location_def(const Zone& root, uint64_t id) {
60 for (auto e : root.reg.view<const LocationKind>())
61 if (root.reg.get<const LocationKind>(e).id == id) return e;
62 return entt::null;
63}

65inline entt::entity find_unit_def(const Zone& root, uint64_t id) {
66 for (auto e : root.reg.view<const UnitKind>())
67 if (root.reg.get<const UnitKind>(e).id == id) return e;
68 return entt::null;
69}
