World 子類專屬的 POD component（跟 common/ 的身分層分開放，因為不是所有 Zone 子類都要）。全部是 POD aggregate + serialize() 成員。鐵律：新增 component 必須同步登記 serialize/all_components.h 的 AllComponents，否則存檔會默默漏掉它（見第 6 站）。

26 行 movement.h 示範「system 該長什麼樣」：簽章 void(Zone&) 即 ZoneSystem，可直接 zm.add_zone_system(systems::movement) 註冊。位置變更一律經 move_by 收口、不直改 Position——將來 tile flag 檢查（可走性）、空間索引維護都掛在這個口上。

看什麼

  • Position{x,y,z}：z 即 Zone::layers 的鍵；有 .x/.y 故滿足 tdarray 的 is_coor concept。 position.h:7
  • Velocity{dx,dy}：每 tick 移動步（示範用）。 velocity.h:5
  • move_by：位置變更的唯一入口。 movement.h:12
  • movement：view 遍歷帶 entity，交給 move_by。 movement.h:20
讀完該能回答：新增一個 component 除了寫 struct 本身，還必須改哪個檔？要新增一個 system，需要改 ZoneManager 嗎？

9// 位置變更的唯一入口：直改 Position 僅限 zone 內移動且必經 move_by。
10// 將來 tile flag 檢查（可走性）、空間索引維護都掛在這裡。
11// 現階段僅座標加法；z 不動（Velocity 無 dz，跨層移動屬將來的傳送/樓梯機制）。
12inline void move_by(Zone& z, entt::entity e, int dx, int dy) {
13 auto& p = z.reg.get<Position>(e);
14 p.x += dx;
15 p.y += dy;
16}
17
18// 每個 zone 的 system：讓每個帶有 Velocity 的 actor 前進一步。
19// 簽章即 ZoneSystem，可直接 zm.add_zone_system(systems::movement);
20inline void movement(Zone& z) {
21 z.reg.view<Position, Velocity>().each([&](entt::entity e, Position&, Velocity& v) {
22 move_by(z, e, v.dx, v.dy);
23 });
24}
25
26} // namespace systems
