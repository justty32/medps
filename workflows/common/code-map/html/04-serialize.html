第 4 站 serialize/ — 存讀檔管線

4 個檔案，共 130 行 · 對照 CODE_TOUR.md

分工：registry_io 負責單一 registry ↔ 位元組（EnTT snapshot 遍歷、cereal PortableBinary 決定位元格式、entt_cereal_archive.h 純膠水橋接）；zone_io 負責完整 Zone——第一塊（id/parent/layers）直接 cereal，第二塊（reg）走 registry_io，兩塊依序接在同一 stream。

save 與 load 都以 fold expression 展開 AllComponents type_list——清單漏了誰，那個 component 就「默默」不存不讀，不會報錯。存檔無版本欄位（使用者裁定）：格式一變，舊檔讀出來就是壞資料；重寫期直接刪存檔目錄。

看什麼

  • AllComponents：新增 component 唯一要登記的地方。 all_components.h:8
  • 純膠水：把 entt snapshot 的 callback 簽章轉成 cereal 呼叫，entt::entity ↔ 底層整數。 entt_cereal_archive.h:8
  • save_impl / load_impl 用 fold expression 展開清單。 registry_io.h:16
  • 陷阱點 orphans()：load 後沒有任何（已登記）component 的 entity 會被清掉。 registry_io.h:30
  • 兩塊接合：大括號限制 archive 生存期——cereal 是解構時才把緩衝寫出去的。 zone_io.h:20
讀完該能回答：為什麼新 component 忘了登記 AllComponents，存檔會「默默」漏掉它、不會報錯？

9// 單一 registry 的 snapshot save/load。
10// registry <-> 位元組；要存到哪裡（檔案、pack、DB）不歸這裡管。
11namespace registry_io {
12
13namespace detail {
14
15 template<typename... Cs>
16 void save_impl(entt::registry& reg, output_archive& out, entt::type_list<Cs...>) {
17 auto snap = entt::snapshot{reg};
18 snap.get<entt::entity>(out);
19 (snap.get<Cs>(out), ...);
20 }
21
22 template<typename... Cs>
23 void load_impl(entt::registry& reg, input_archive& in, entt::type_list<Cs...>) {
24 auto loader = entt::snapshot_loader{reg};
25 loader.get<entt::entity>(in);
26 (loader.get<Cs>(in), ...);
27 // orphans() 會銷毀所有最終沒有任何 component 的 entity。
28 // 未登記在 AllComponents 的 component 不只資料會掉，只帶這種 component
29 // 的 entity 本身也會在這裡一併消失。
30 loader.orphans();
31 }
32
33} // namespace detail
34
35inline void save(entt::registry& reg, std::ostream& os) {
36 cereal::PortableBinaryOutputArchive cereal_out{os};
37 output_archive out{cereal_out};
38 detail::save_impl(reg, out, AllComponents{});
39}
40
41inline void load(entt::registry& reg, std::istream& is) {
42 cereal::PortableBinaryInputArchive cereal_in{is};
43 input_archive in{cereal_in};
44 detail::load_impl(reg, in, AllComponents{});
45}
46
47} // namespace registry_io

26}
