第 2 站 zone.h + tile.h — 核心資料結構

2 個檔案，共 55 行 · 對照 CODE_TOUR.md

zone id 是零座標語意的裸 uint64_t 單調序號（舊 ZoneKey 位元打包已移除）；層級只活在 parent 鏈上。ZONE_ROOT=0 永駐、沒有地圖，放非地圖的全局實體。

layers 是 map<int, tdarray<Tile>>，鍵即 z（地面=0、往下為負、稀疏）。地圖是 zone 的固有結構、不走 ECS——代價是 registry snapshot 不含它，存檔由 zone_io 分兩塊處理（見第 4 站）。

看什麼

  • Tile{terrain, flags}：不是 component；flags 快取通行性。 tile.h:12
  • TILE_WALKABLE / TILE_BLOCKS_SIGHT 通行 flags。 tile.h:9
  • Zone 本體：身分直接掛 struct，不再用 placeholder entity 攜帶。 zone.h:19
  • layers：鍵即 z 的稀疏多層地圖。 zone.h:36
  • registry 不可複製 → Zone 只能移動。 zone.h:27
讀完該能回答：為什麼地圖掛在 Zone 上而不是做成 component？代價是什麼？（答案在 layers 的註解。）

8// root zone 的固定 id。它永久存活、沒有地圖，放的是非地圖的全局實體
9//（陣營 / 神祇 / 具名角色）。root 的 parent 就是它自己。
10inline constexpr uint64_t ZONE_ROOT = 0;
11
12// 一個 zone = 一個獨立的 entt::registry，加上它自己的身分。
13//
14// 身分直接掛在 Zone 上，不再由 registry 內部的 placeholder entity 攜帶
15//（舊做法是 ZoneMeta component，已移除）。好處是不必為了「讓 zone 有身分」
16// 而保證 registry 裡永遠有一個活著的 entity。
17//
18// 注意：entt::registry 不可複製，因此 Zone 也不可複製，只能移動。
19struct Zone {
20 // 全局唯一識別。原本 ZoneKey 的位元打包（type/x/y/z）已移除，
21 // 這裡先用裸整數佔位；分層與座標語意待重新設計。
22 uint64_t id{};
23
24 // 直接父 zone 的 id；與自己相同時代表沒有父層。
25 uint64_t parent{};
26
27 entt::registry reg;
28
29 // 地圖：一個垂直層一張 tile 格網，鍵就是 z（以地面為中心，往下為負）。
30 // 用 map 而非 vector：層是稀疏的（多數 zone 只有地面層），z 可以是負數，
31 // 而且日後往上下擴充不必重新編號。
32 //
33 // 直接掛在 Zone 上，不走 ECS——地圖是 zone 的固有結構，不是某個 entity 的屬性。
34 // 代價：它不在 registry 裡，所以 registry_io 的 snapshot 不會碰它，
35 // 存檔由 serialize/zone_io.h 分兩塊處理。
36 std::map<int, tdarray<Tile>> layers;
37};
