第 2 站 zone/zone.h + tile.h + zone.cpp — 核心資料結構

3 個檔案，共 100 行 · 對照 CODE_TOUR.md

zone id 是零座標語意的裸 uint64_t 單調序號；層級只活在 parent 鏈上。ZONE_ROOT=0 永駐、沒有地圖，放非地圖的全局實體（陣營/神祇/具名角色）。

layers 是 map<int, tdarray<Tile>>，鍵即 z（地面=0、往下為負、稀疏）。地圖是 zone 的固有結構、不走 ECS——代價是 registry snapshot 不含它，存檔由 zone_io 分兩塊處理（見第 6 站）。

Zone 是繼承基底：virtual dtor 使隱式 move 被抑制——Zone 不可複製也不可移動，一律經 unique_ptr/參照持有，子類物件切片結構上不可能發生。ZoneKind 是存檔 kind tag（續編只加號、不重排）；make_zone 依 tag 建構對應子類（未知 tag throw）；zone_cast<T> 是型別安全向下轉型。save_extra/load_extra 是子類專屬資料的序列化掛鉤，基底 no-op；目前唯一子類 World 見第 5 站。

看什麼

  • Tile{terrain, flags}：不是 component；flags 快取通行性。 tile.h:12
  • TILE_WALKABLE / TILE_BLOCKS_SIGHT 通行 flags。 tile.h:9
  • Zone 本體：身分直接掛 struct，不再用 placeholder entity 攜帶。 zone.h:28
  • layers：鍵即 z 的稀疏多層地圖。 zone.h:44
  • virtual dtor：抑制隱式 move/copy，子類只能經指標/參照持有。 zone.h:46
  • ZoneKind：存檔 kind tag，Plain=0／World=1。 zone.h:17
  • save_extra/load_extra：子類專屬資料的序列化掛鉤。 zone.h:55
  • zone_cast：型別安全向下轉型。 zone.h:66
  • make_zone 工廠實作：未知 kind throw，絕不靜默退回 Plain。 zone.cpp:6
讀完該能回答：為什麼地圖掛在 Zone 上而不是做成 component？子類要序列化自己的資料，該覆寫哪兩個掛鉤？

10// root zone 的固定 id。它永久存活、沒有地圖，放的是非地圖的全局實體
11//（陣營 / 神祇 / 具名角色）。root 的 parent 就是它自己。
12inline constexpr uint64_t ZONE_ROOT = 0;
13
14// zone 的具體型別，序列化時寫進 zone 檔頭（uint8），load 讀 tag 後經 make_zone
15// 建構對應子類。續編規則：新子類往後加號、不重排；未知值＝存檔損毀（make_zone throw）。
16// kind 不進 zone id——id 維持零語意單調序號。
17enum class ZoneKind : uint8_t { Plain = 0, World = 1 };
18
19// 一個 zone = 一個獨立的 entt::registry，加上它自己的身分。
20//
21// 身分直接掛在 Zone 上，不再由 registry 內部的 placeholder entity 攜帶
22//（舊做法是 ZoneMeta component，已移除）。好處是不必為了「讓 zone 有身分」
23// 而保證 registry 裡永遠有一個活著的 entity。
24//
25// Zone 是繼承基底（第一個子類：World，見 world.h）。virtual dtor 使隱式
26// move 被抑制——Zone 不可複製也不可移動，一律經 unique_ptr / 參照持有
27//（ZoneManager 本就如此），子類物件切片在結構上不可能發生。
28struct Zone {
29 // 全局唯一識別：零座標語意的單調序號，由 ZoneManager::create_child 配發。
30 uint64_t id{};
31
32 // 直接父 zone 的 id；與自己相同時代表沒有父層。
33 uint64_t parent{};
34
35 entt::registry reg;
36
37 // 地圖：一個垂直層一張 tile 格網，鍵就是 z（以地面為中心，往下為負）。
38 // 用 map 而非 vector：層是稀疏的（多數 zone 只有地面層），z 可以是負數，
39 // 而且日後往上下擴充不必重新編號。
40 //
41 // 直接掛在 Zone 上，不走 ECS——地圖是 zone 的固有結構，不是某個 entity 的屬性。
42 // 代價：它不在 registry 裡，所以 registry_io 的 snapshot 不會碰它，
43 // 存檔由 serialize/zone_io.h 分兩塊處理。
44 std::map<int, tdarray<Tile>> layers;
45
46 virtual ~Zone() = default;
47
48 // 型別由 virtual 回答、不另存欄位——杜絕「欄位與實際型別不一致」一族錯誤。
49 // 子類 override 時回傳自己的 KIND。
50 static constexpr ZoneKind KIND = ZoneKind::Plain;
51 virtual ZoneKind kind() const { return KIND; }
52
53 // 子類專屬資料的序列化掛鉤，由 zone_io 在第一塊（id/parent/layers 之後）呼叫。
54 // save / load 必須成對對稱——欄位漏寫即後續位元流整批錯位。基底無專屬資料，no-op。
55 virtual void save_extra(cereal::PortableBinaryOutputArchive&) {}
56 virtual void load_extra(cereal::PortableBinaryInputArchive&) {}
57};
58
59// 工廠：依 kind 建構對應子類（zone_io::load 讀檔頭 tag 後、ZoneManager 建 zone 時呼叫）。
60// 未知 kind＝存檔損毀，throw；絕不靜默退回 Plain。
61std::unique_ptr<Zone> make_zone(ZoneKind kind);
62
63// 型別安全的向下轉型：kind 相符回傳子類指標，否則 nullptr。
64// if (auto* w = zone_cast<World>(zm.get(id))) w->generate();
65template <class T>
66T* zone_cast(Zone* z) {
67 return (z && z->kind() == T::KIND) ? static_cast<T*>(z) : nullptr;
68}
