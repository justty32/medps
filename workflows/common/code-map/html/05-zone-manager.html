2 個檔案，共 224 行 · 對照 CODE_TOUR.md

root 永久存活、放全局實體，其餘 zones 按需載入卸載。header 註解寫了三條契約，必讀：tick 內禁止 zone 結構性變更（迭代器 UB）；存檔目錄=單槽活儲存；Zone* 不跨 tick 持有（想長駐就存 id、每次 get）。

存檔佈局：一 zone 一檔（<16hex>.bin，root 特例 root.bin）＋ manifest.bin（僅 next_zone_id，未來擴充為存檔 metainfo）。

看什麼

  • 開檔協定：有 manifest → 還原 next_id＋必讀回 root.bin（缺失 throw）；無 manifest 但有 .bin → throw；乾淨目錄 → 新世界。 zone_manager.cpp:9
  • create_child：id 單點配發（永不復用），配發即原子寫 manifest；撞既有檔或 parent 未載入 → throw。 zone_manager.cpp:47
  • destroy：連盤上檔案一起刪（死 zone 不復活）。 zone_manager.cpp:60
  • manifest 原子寫：先 .tmp 再 rename。 zone_manager.cpp:79
  • load：檔案不存在回 false；檔內 id 與請求不符 → throw。 zone_manager.cpp:97
  • tick：每個已載入 zone × 每個 system 依註冊順序；root 也參加。 zone_manager.cpp:126
讀完該能回答：哪三種磁碟狀態會讓建構子 throw？為什麼 create_child 要在建 zone 前先寫 manifest？

97bool ZoneManager::load(ZoneId id) {
98 if (zones_.count(id)) return true; // 已在記憶體中
99
100 auto p = path(id);
101 if (!std::filesystem::exists(p)) return false;
102
103 auto zone = std::make_unique<Zone>();
104 std::ifstream ifs{p, std::ios::binary};
105 zone_io::load(*zone, ifs); // id / parent 由檔案內容還原
106 if (zone->id != id)
107 throw std::runtime_error(
108 "ZoneManager::load: 檔案內容 id 與請求不符（存檔損毀）: 請求=" + std::to_string(id) +
109 " 檔內=" + std::to_string(zone->id));
110 zones_.emplace(id, std::move(zone));
111 return true;
112}

114void ZoneManager::unload(ZoneId id) {

120}
