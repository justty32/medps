第 3 站 components/ — 資料積木

6 個檔案，共 95 行 · 對照 CODE_TOUR.md

全部是 POD aggregate + serialize() 成員；entity 之間的參照存 entt::entity。快速掃過即可，但三個「非典型」的要細看。

鐵律：新增 component 必須同步登記 serialize/all_components.h 的 AllComponents，否則存檔會默默漏掉它（見第 4 站）。

看什麼

  • ZoneMeta：每個 zone 的 placeholder entity 持有，保證 zone 至少有一個非孤兒 entity（跟第 4 站 orphans() 互相咬合），也記錄 self/parent key。 zone_meta.h:7
  • WorldConfig：singleton 掛在 ROOT 上，per-save 不可變（world_dim 已烘進 key 運算）。 world_config.h:10
  • AreaTerrain：密集 terrain grid 掛在單一「map」entity 上；tile 不是一格一 entity。通行性兩層：terrain flags（這裡）+ 逐 entity 的 Blocking。 area_terrain.h:22
  • Blocking：疊在 terrain 之上的逐 entity 阻擋（門、巨石、大型生物）。 blocking.h:5
  • Position 有 .x/.y，因此滿足 tdarray 的 is_coor concept。 position.h:6
讀完該能回答：為什麼遊戲中途不能改 world_dim？為什麼每個 zone 一定要有一個帶 component 的 placeholder entity？

2#include <cstdint>
3#include "../zone_key.h"
4
5// 每份存檔的全域世界設定。以 SINGLETON component 掛在 ROOT 上，因此會跟著
6// root 走正常的 snapshot/cereal 存檔路徑（由 save_all 寫出、load_root 還原）
7// -- 不需要另外的 meta 檔。在世界生成時決定，且在該存檔的整個生命週期內 IMMUTABLE：
8// world_dim 已內嵌進 ZoneKey 的座標語意，遊戲中途更動會讓所有既有 key 失效。
9// 需要它的 system 以 `const WorldConfig&`（自由函式風格）取用。
10struct WorldConfig {
11 // 世界地圖 = world_dim_x × world_dim_y 個 world-tile（大陸 + 海洋）。新遊戲時可由
12 // 玩家選擇（小 / 中 / 大）；x、y 必須滿足 zone_scale::valid_world_dim。
13 int16_t world_dim_x{zone_scale::WORLD_DIM_DEFAULT};
14 int16_t world_dim_y{zone_scale::WORLD_DIM_DEFAULT};
15 // 垂直層數（z 軸）。預設 3 = Underground/Ground/Sky（−1/0/1）；保留此欄位以便
16 // 日後擴充更多層（冥界、天界…）。
17 int16_t world_dim_z{zone_scale::WORLD_LAYERS_DEFAULT};
18
19 template<class Archive>
20 void serialize(Archive& ar) { ar(world_dim_x, world_dim_y, world_dim_z); }
21};

5// Area terrain grid 中的一格。`terrain` 是 def id（由內容 / 前端對映到視覺呈現）；
6// `flags` 快取與模擬相關的通行性，讓 FOV / 尋路不必每格去查 terrain def。
7inline constexpr uint8_t TILE_WALKABLE = 1 << 0;
8inline constexpr uint8_t TILE_BLOCKS_SIGHT = 1 << 1;
9
10struct Tile {
11 uint16_t terrain{0};
12 uint8_t flags{0};
13
14 template<class Archive>
15 void serialize(Archive& ar) { ar(terrain, flags); }
16};
17
18// 一個 Area zone 的密集 terrain grid（Rimworld 風格，約 250x250）。以 component 掛在
19// 單一「map」entity 上，因此會跟著走正常的 snapshot/cereal 存檔路徑
20// -- registry ctx() 不會被 zone_io 序列化。可移動的「things」（actor、
21// item）是各自獨立的 entity；tile 並非一格一個 entity。
22struct AreaTerrain {
23 tdarray<Tile> tiles; // 維度大小存在 tiles.sx / tiles.sy
