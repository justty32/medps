# resync — 使用者親改程式碼後的接手流程

觸發語：「我改了 code，你接手」「我 X 點之後有改東西」「去看我留的註解」。

開始前寫 `Done when: <使用者變更已定位、已讀懂、測試綠、CODE_MAP/CODE_TOUR 已同步、理解與疑問已回報>`。

## DAVID 標記協定

使用者會在程式碼裡留三種標記（完整慣例見 [common/conventions.md](common/conventions.md)）：

| 標記 | 意義 | agent 的動作 |
|------|------|--------------|
| `// DAVID: <指令>` | 給 agent 的待辦/指引 | 執行它；完成後**刪除該註解**；無法立即處理或需討論 → 搬到 [../SESSION-LOG.md](../SESSION-LOG.md) 並回報，註解保留 |
| `// DAVID_WRITE:` … `// DAVID_WRITE_END:` | 使用者親寫的程式碼區塊 | 讀懂並接線；**不改寫其中邏輯**（編譯錯誤、格式可修但要回報）；標記本身不主動刪，使用者叫你清才清 |
| 沒有標記，只說時間 | 「我 X 點後改的」 | 走下面的定位步驟 |

掃描指令：

```bash
grep -rn 'DAVID' src/ test/ --include='*.h' --include='*.hpp' --include='*.cpp'
```

## 流程

1. **定位變更**
   - 優先 `git diff`（含 `git status` 看新檔）；若使用者給了時間點且 working tree 混有 agent 自己的變更，用檔案時間輔助：
     ```bash
     find src test -newermt '2026-07-10 14:30' -type f
     git log --oneline --since='14:30'   # 若使用者有自己 commit
     ```
2. **掃 DAVID 標記**（上面的 grep），按協定分類處理。
3. **逐檔讀懂變更**：不只看 diff 行，讀進上下文；推斷使用者的意圖。
4. **跑測試**：見 [testing.md](testing.md)。紅燈不代表使用者錯——先判斷是變更未完成、還是既有測試該改。
5. **同步文檔鏈**：CODE_MAP → CODE_TOUR → 其他受影響文檔。
6. **回報**：用自己的話覆述「你做了什麼、為什麼」＋列出疑問或發現的問題。**理解錯誤要在這裡被抓到**，所以覆述要具體（路徑:行號）。
7. 使用者的變更方向若與現有設計文檔/不變量衝突，先指出，不要擅自「修正」使用者的程式碼。

## 給使用者的最佳實踐（降低接手成本）

- 下場改碼前喊一聲，讓 agent 先把自己的工作 commit——git diff 就能乾淨隔離你的變更。
- 懶得加標記沒關係，時間點定位夠用；但**跨檔的意圖**（「這三個檔的改動是同一件事」）用一句話講比 agent 自己猜快。

## 何時不用

- 使用者只是口頭給指示、沒碰程式碼 → 直接走對應工作流（feature-dev/refactor/…）。
- 變更微小且使用者已說清楚內容 → 直接做，不必走完整流程。
